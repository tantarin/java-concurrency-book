# Что такое поток

> Process, stack и heap

← [Зачем приложениям несколько потоков](./02-why-multiple-threads.md) · [Где JVM хранит данные](./03-java-memory.md) →

При запуске Java-приложения операционная система создаёт процесс. Внутри него JVM может создать несколько потоков выполнения. У каждого потока есть собственный стек вызовов — контекст методов, которые он сейчас выполняет.

Объекты обычно находятся в общей [heap-памяти](./03-java-memory.md#heap-память-объектов). Поэтому два потока могут получить ссылки на один объект и одновременно вызвать его методы.

```java
Java-процесс

Thread 1 → свой stack ┐
Thread 2 → свой stack ├── общая heap
Thread 3 → свой stack ┘
```

Почему здесь участвует операционная система, если потоки созданы внутри Java-процесса? Обычный Java-поток — точнее, **platform thread (платформенный поток)** — современные JVM, как правило, связывают с нативным потоком операционной системы один к одному. JVM создаёт объект `Thread`, подготавливает его stack (стек) и просит ОС создать соответствующий системный поток.

```text
Java Thread (platform)
        ↓ JVM связывает 1 : 1
нативный поток ОС
        ↓ планировщик ОС назначает
ядро процессора
```

Только операционная система распределяет ядра процессора между всеми потоками всех запущенных процессов. Поэтому именно её планировщик решает, какой нативный поток сейчас получит процессорное время, а какой будет ждать. JVM может задать приоритет или перевести Java-поток в состояние ожидания, но не может самостоятельно выдать ему физическое ядро.

Планировщик может остановить platform thread между двумя операциями и продолжить другой. Java не гарантирует конкретный порядок таких переключений, поэтому нельзя полагаться на порядок, который случайно наблюдался в нескольких запусках.

У [**virtual threads (виртуальных потоков)**](./18-virtual-threads.md) появляется дополнительный уровень: планировщик JVM назначает множество виртуальных потоков на небольшое число platform threads — их называют **carrier threads (потоками-носителями)**. Но сами carrier threads по-прежнему планирует операционная система.

```text
virtual threads
      ↓ планировщик JVM
carrier platform threads
      ↓ планировщик ОС
ядра процессора
```

> Опасное сочетание — несколько потоков, общее состояние и возможность его изменить.

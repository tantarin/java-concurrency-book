# Как теряется инкремент

> Race condition и atomicity

← [Наш сервис просмотров](./04-shared-mutable-state.md) · [Подробнее о race condition](./05-race-condition-details.md) →

`count++` выглядит одной операцией в исходном коде. Но по смыслу поток должен прочитать значение, вычислить новое и записать его обратно.

```java
count = 0

Thread 1: прочитал 0
Thread 2: прочитал 0
Thread 1: записал 1
Thread 2: записал 1
```

Оба запроса завершились без исключения, однако результат равен `1`. Второй поток записал значение, рассчитанное из устаревшего нуля. Один инкремент потерялся.

Это [**race condition**](./05-race-condition-details.md): результат зависит от того, как перемешались действия потоков. Требование выполнить несколько шагов как одно неделимое действие называется **atomicity**.

> Ошибка может проявляться редко. Удачный запуск не доказывает, что код потокобезопасен.
